# 接口

## 契约

接口必须先定义契约, 再编写实现. 契约位于 `contract/routes/`, 端点通过 `contract/endpoint.ts` 的构造器声明路径, 参数, 响应, 鉴权与二次验证要求以及业务码, 公共响应结构位于 `contract/types.ts`.

前端只从契约获取类型, 不引入契约层的运行时; `src/apis/` 按业务域手写函数, 参数与返回值以契约类型标注.

新增接口时, 契约, `server/routes/` 下的 mock, `src/apis/` 与 `src/config/query.ts` 应同时补齐, 缺一视为未完成.

`server/` 消费同一份契约, 处理器集合在 `server/routes/index.ts` 汇总, 与契约的业务域一一对应, 名称不一致时服务启动即失败.

`server/middleware.ts` 依据契约中的附加信息执行前置校验; 处理器返回的业务码未在契约中声明时, 直接终止进程.

## 码表与环境

业务码集中在 `shared/codes.ts`, 按通用, 鉴权, 上游分层, 不得书写裸数字. 环境变量集中在 `shared/env.ts` 解析并以对象导出, 业务代码不得读取原始变量.

前端不得假设响应结构. 传输层失败与业务失败分别表达, 仅传输层失败允许重试, 业务失败交由调用方决定提示方式.
